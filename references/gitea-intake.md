# Gitea intake

`task-brief-to-pr mcp/libbpf-mcu:pr6` selects Gitea owner `mcp`, repository `libbpf-mcu`, and ref `pr6`. All three fields identify the source of the brief. This form works for a first task before GitHub has assigned a PR number.

1. Use an explicitly supplied Gitea repository and ref when present. Otherwise get the project repository name from the workspace's Git remote and the PR number from the current task or verified PR metadata. Find the Gitea repository with that exact name and use its `pr<N>` branch. For example, project `xpost` and PR #23 map to Gitea `xpost`, branch `pr23`. Resolve the Gitea owner with `search_repos` when it is unknown. Ask for the missing owner or PR number if the context and lookup leave multiple candidates.
2. Use the local `magpie` provider's Gitea tools (`mcp__magpie__gitea__…`). Resolve the ref to a commit SHA. For a branch, use its `commit_sha` from `list_branches`. Use that SHA for directory listings and file reads. Call `get_file_contents` with `path` omitted to list the root, then with each file path to retrieve the root `taskbook.md` and accompanying regular files. Retrieve full contents and decode the response if needed. The branch already contains unpacked files. Save them in a temporary directory outside the implementation checkout with their relative paths intact.
3. Confirm that the complete brief and supporting files are readable before intake. If the ref, brief, or expected file is unavailable, identify the missing item and ask for a usable source. The Gitea ref supplies the documents. Resolve the implementation branch and PR base from the target repository in step 1 of the skill. Import the downloaded files in step 2 before implementation.
