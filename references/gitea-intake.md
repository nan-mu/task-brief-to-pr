# Gitea intake

`task-brief-to-pr mcp/libbpf-mcu:pr6` selects Gitea owner `mcp`, repository `libbpf-mcu`, and ref `pr6`. All three fields identify the source of the brief. This form works for a first task before GitHub has assigned a PR number.

1. Use an explicitly supplied Gitea repository and ref when present. Otherwise get the project repository name from the workspace's Git remote and the PR number from the current task or verified PR metadata. Find the Gitea repository with that exact name and use its `pr<N>` branch. For example, project `xpost` and PR #23 map to Gitea `xpost`, branch `pr23`. Resolve the Gitea owner with `search_repos` when it is unknown. Ask for the missing owner or PR number if the context and lookup leave multiple candidates.
2. Use the local `magpie` provider's Gitea tools (`mcp__magpie__gitea__…`). Resolve the ref to a commit SHA. For a branch, use its `commit_sha` from `list_branches`. List the tree with `get_repository_tree` at that SHA, including nested paths such as `tests/<test-name>.md`. Page through the tree or use directory listings at the same SHA if the result is incomplete. Retrieve the root `taskbook.md` and supporting regular files with `get_file_contents` at that SHA. Decode the response if needed. Save the files in a temporary directory outside the implementation checkout with their relative paths intact. Keep the source repository, requested ref, resolved branch when known, and pinned SHA with the download for worktree handoff.
3. Confirm that the complete brief and supporting files are readable before intake. If the ref, brief, or expected file is unavailable, identify the missing item and ask for a usable source. Resolve the implementation branch and PR base from the target repository in step 1 of the skill. Import the downloaded files in step 2 before implementation.

## Recover the PR's taskbook history

1. Use the Gitea branch verified for this PR. For a revision supplied locally or by a SHA or tag, use the earlier intake's `Taskbook-Source` and PR metadata to identify the task branch. Check the normal `pr<N>` mapping when the original source is unclear. If a task branch was renamed or moved to a different PR number, verify the link to its earlier revisions before using them. Keep the selected taskbook SHA fixed even if the branch has advanced.
2. Page through `list_commits` from that fixed SHA with `path: "taskbook.md"`. Read the original and subsequent versions belonging to this PR with `get_file_contents` at their commit SHAs. Use known delivery SHAs from earlier intake commits or audit records to recover published snapshots. Check the history of referenced verification and decision files too when an attachment changed without a change to the root brief. Resolve each historical attachment at its revision's SHA, since a later revision can edit or remove a file at the same path. Keep historical files in the evidence directory with their source SHA, separate from the current intake files.
3. Read applicable user decisions from the brief, its pinned sources, and recorded implementation clarifications. Look up the project's shared `decisions.md` and referenced ADRs on Gitea `main` when relevant, with the read pinned to a commit. Bring forward prior PR audit evidence that still applies. For a task with a verified local-only history, recover earlier intake and clarification commits from the implementation branch. If an expected source or history is missing, record the specific gap and leave continuity unverified. Continue separable work.
