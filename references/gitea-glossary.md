# Project glossary in Gitea

1. Through the local Magpie Gitea MCP, find the Gitea repository with the same name as the implementation project, using the repository lookup in [Gitea intake](gitea-intake.md). Use its default branch for the shared glossary. Read the root `GLOSSARY-MAP.md` and the glossaries it points to for the affected contexts when a map exists. Otherwise read the root `GLOSSARY.md`.
2. If the applicable glossary is missing, start Matt Pocock's `mattpocock-skills:domain-modeling` before implementing. Use the brief, project docs and code, and any existing project glossary to establish the first project-specific terms. When the first term is resolved, create the glossary in Matt's format at its mapped path, or at `GLOSSARY.md` in the root for a single context. Follow the same skill when defining, changing, or reconciling terms in an existing glossary. If Gitea is unavailable, report it and use the available project terminology for the current task.
3. Write resolved terms back to the Gitea default branch with `create_or_update_file`. Include the existing file SHA for updates. If a concurrent edit changes the file, read the latest version and incorporate the resolved terms without overwriting the other edit. Give Matt's skills the glossary text or readable temporary copies with the same relative paths when they need local files.
